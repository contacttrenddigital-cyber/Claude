# Обновяване и преглед на данните

```
1. npm run sources:fetch     # сваля отново първичните файлове; при нов SHA-256 пази новия файл отделно и спира с код 2
2. npm run extract           # DOCX таблици + EMF Приложение № 3 → data/extracted/
3. npm run snapshot:build    # извличане, кръстосани проверки, равенства, сравнение със СИГМА → data/snapshots/snap-<hash>.json
                             # спира без запис, ако има неуспешна проверка
4. npm run db:seed           # зарежда снимката в PostgreSQL (идемпотентно), НЕ публикува
5. преглед: /iztochnitsi на локален сървър, предупрежденията в снимката, git diff на снимката
6. npm run db:publish -- "Име на редактора"   # публикува; записва AuditLog; предишната снимка става superseded
```

## Правила
- Нищо не се публикува автоматично от scraping или AI извличане. Публикуването е изрично действие с име.
- Снимка с неуспешна проверка не може да се публикува.
- Променен документ (нов SHA-256) не презаписва стария: внася се като нов документ и нова снимка.
- Сайтът чете само публикуваната снимка от базата. Ако външен източник е недостъпен, сайтът продължава да работи с последната публикувана снимка.
- **Текущо състояние:** снимка `snap-aeff82bb419fbe33`, публикувана от „Claude (автоматична проверка)“. **Редакторско одобрение от човек още няма.** Сайтът го казва във футъра.

## HTML източници
Страниците на government.bg съдържат динамичен markup и SHA-256 се сменя при всяко зареждане. За тях `sources:fetch` ще отчита „changed“. Сравнявай извлечения текст, а не байтовете (предстои автоматизиране).

## Следене на законопроектите в Народното събрание
```
npm run bills:track      # API на НС за 52-602-01-71, -68, -70; нов отговор → data/raw/parliament/bill_<id>.<дата>.json + bills.json
npm run snapshot:build   # етапите влизат в хронологията (документ ns-api-bill-<id>-<sha8>)
npm run db:seed && npm run db:publish -- "Име"
```
- Код 2 = има промяна: нови доклади на комисии, гласуване в зала или обнародване. Етапите се извеждат от `src/lib/legislation/parliament.ts` (тестван с реални отговори на API: текущия законопроект и вече обнародван закон).
- Документите в базата са неизменни: всеки нов отговор на API получава нов id (`…-<sha8>`), старите остават в историята.

### Когато законът бъде обнародван
1. `bills:track` показва „ОБНАРОДВАН: ДВ бр. …“; страницата `/zakonodatelstvo` показва предупреждение, че числата още са от законопроекта.
2. Изтегли текста от „Държавен вестник“ (нужен е достъп до dv.parliament.bg — не е в разрешените хостове на облачната среда, поискай го) и окончателния текст от НС.
3. Добави нова версия (`stage: "PROMULGATED"`) в `scripts/build-snapshot.ts`, извлечи таблиците и сравни с внесения законопроект (`versionDiffs`), за да се видят промените между първо и второ четене.
