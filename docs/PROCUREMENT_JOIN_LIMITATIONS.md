# Договори и плащания: ограничения

**Статус: не е изградено.** `/dogovori` не съществува. `/izpalnenie` показва само програма срещу отчет по КФП (Приложение № 1).

## Защо
- Централизираната система за обществени поръчки (ЦАИС ЕОП) и отворените данни за договори не са в разрешените хостове на облачната среда и не са проверени.
- Бюджетните редове (функции, тавани, проекти) и поръчките нямат общ публикуван идентификатор. Изключение са номерата на приоритетните проекти (NP-…), но те още не са свързани с поръчки.

## Как ще се свързва
1. Ключове: ЕИК на възложителя, номер на проект (NP-…), уникален номер на поръчката. Никога само по име.
2. Всяко свързване се записва с източник и ниво на увереност (точен ключ, съвпадение по име, ръчно потвърдено).
3. Етапи: предложено → прието → договорено → платено. Липсващ етап се показва като липсващ, не като нула.
4. Без изводи за нарушения. Разминаванията се показват като въпроси с право на отговор.
